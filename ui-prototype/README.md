# UI 原型 v1 · 说明

这是《需求-v1.md》F8 的**可交互界面原型**，用纯 HTML/CSS/JS 实现，不依赖构建工具、不连接 DSH、不写任何真实数据。目的：在写插件代码前先确认信息架构、字段与交互，减少返工。

## 打开方式

两版原型：

- **第一版** `index.html`：任务列表 + 新建/编辑 + 提醒浮层 + 设置（F8 全貌）
- **第二版** `board.html`：待办/已完成/超期三视图 + 派生优先级 + 置顶（用户追加需求）

```bash
open ui-prototype/index.html    # 第一版
open ui-prototype/board.html    # 第二版
```

第二版 URL 参数：`?tab=done`、`?tab=overdue`、`?dark=1`、`?clean=1`。

URL 参数（便于截图/评审）：

| 参数 | 作用 |
|---|---|
| `?clean=1` | 隐藏左下角「原型工具条」，得到干净界面 |
| `?view=settings` | 直接打开设置页 |
| `?view=new-recurring` | 直接打开「新建循环任务」弹窗 |
| `?view=new-once` | 直接打开「新建单次任务」弹窗 |
| `?view=overlay` | 直接展示提醒浮层 |
| `?dark=1` | 深色主题 |

## 第二版（board.html）已体现的需求点

- F4.10 / F8.11 三视图页签与计数徽标（待办 / 已完成 / 超期）
- F4.11 `dueDate` 截止日期（不产生提醒，只用于分组/超期/优先级）
- F4.12 派生优先级：`daysLeft ≤ 0` 高、`1–3` 中、`4–7` 低、`>7` 或无截止 无
- F4.13 每日 00:05 自动重算（原型里「↻ 重算优先级」按钮模拟，真实实现由宿主 tick 完成）
- F4.14 置顶：📌 按钮、置顶组置顶、淡琥珀底
- F4.15 完成时自动取消置顶并写入完成时间
- F8.12 优先级规则说明条
- F8.13 置顶交互与视觉
- F4.16–F4.19 / D-24 已完成季度归档（「已完成」页签可切「本季度 / 2026-Q3 / 2026-Q2」）
- F4.10 / D-22 暂停任务单独成「已暂停」组：不算超期、不参与优先级、不计入待办徽标

## 第一版（index.html）已体现的需求点

- F8.1 侧边栏「待办提醒」入口（`sidebar.panellist`，`id=todos-diy`）
- F8.2 主面板：分组列表（今天 / 未来 7 天 / 已暂停 / 已错过）+ 右侧详情（时区、下次触发、例外日、最近记录）
- F8.3 提醒浮层：≤3 条逐条 + 「还有 N 条」折叠条；已完成/已错过用不同色标
- F8.4 空态 / 加载态 / 错误态（原型只展示正常态与空态，三态在实现时补齐）
- F8.5 表单：循环/单次切换；四条规则类型（工作日、每周、每月、自定义 cron）动态显示字段；例外日 chips；未来 5 次触发预览
- F2.5 例外日：`skipDates`（跳过国庆）+ `extraWorkdays`（补班周日）
- F3.3 单次任务提醒节点：仅开始 / 开始和结束 / 仅结束
- F5.4 提醒内容模板：卡片上显示任务名、时间、说明
- F5.7 提前量：编辑器内「提前量 0–1440 分钟」
- F5.8 提示音开关
- F9.1 / F9.2 / F9.3 设置页：默认时区、免打扰（默认关）、提醒方式（浮层必选 + 会话可选 + 系统通知需授权）
- F9.4 导入导出入口

## 交互演示

- 顶部筛选「全部 / 今天 / 未来 7 天 / 已暂停 / 已错过」+ 搜索
- 行内 ⏸ / ▶ 按钮可即时暂停、恢复，侧边栏计数同步变化
- 「＋ 新建任务」打开编辑器；类型卡切换表单
- 「演示提醒浮层」弹出提醒卡片；点击「完成本次 / 稍后 / 关闭」卡片消失并 toast
- 右上角 ◐ 切换深浅色
- 左下角原型工具条可在各视图间跳转（`?clean=1` 时隐藏）

## 与需求的差异（刻意保留的待拍板点）

1. **单次任务默认提醒节点**：原型默认「开始和结束」，需求-v1 暂定默认 `start`，等 D-03 拍板。
2. **月末策略**：原型写「每月最后一天 17:00」，需求-v1 的 `monthly` 只支持 1–31 号，`lastDay` 在 P2；这里作为 D-05 的讨论样例。
3. **「已错过」提醒卡片**：原型展示「不会自动补发」，需求-v1 的 `graceMinutes=5` 内仍会补一次；这条文案要按 D-06 最终口径改。
4. **「原会话 follow-up」** 在原型中作为可勾选项；需求-v1 标为 P1 待 D-02 拍板。
5. **系统通知**：原型只展示「未授权 + 请求权限」状态，实际权限流程在 F9.3 定义。

## 不做什么

- 不实现真实调度、持久化、HTTP API、Agent 工具
- 不引入任何第三方 UI 框架（只用原生 HTML/CSS/JS）
- 不模拟 DSH 的真实 `shell.overlay` / slot 机制，仅做视觉与交互原型
