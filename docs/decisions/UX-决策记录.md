# UX 决策记录（实现方代为决策）

> 日期：2026-10-30 ｜ 决策人：插件实现方（按「减少打扰、减少误操作、默认可用」三条原则）
> 适用范围：v1。用户可随时推翻任一决策；被推翻的条目回写到《待讨论-缺口清单.md》。

## 决策原则

1. **默认可用**：装完就能用，不需要先配置。需要配置的项默认关闭，在设置页显式开启。
2. **减少误操作**：破坏性操作必须可撤销或二次确认；能不做选择就不让用户选。
3. **减少打扰**：提醒要显眼但不挡路；同一件事不重复提醒；夜间不打扰。
4. **可解释**：用户能看懂「为什么这条是高优先级」「为什么这条没提醒」。

---

## UX-01 提醒浮层不自动消失

- **决策**：浮层出现后**不自动关闭**，必须用户点「完成本次 / 稍后提醒 / 关闭」之一。
- **理由**：自动消失的 toast 在用户离开座位时等于没提醒；本项目是「工作待办」，漏看代价高。对照组：dsh-todo-reminder 用 toast + 音效，但那是轻量待办。
- **代价**：用户可能积压多条浮层。缓解：≤3 条逐条显示、>3 条折叠、≥10 条摘要。

## UX-02 完成 / 删除提供 5 秒撤销

- **决策**：完成任务或软删除后，右下角出现「已完成 · 撤销」toast，5 秒内可撤销；撤销直接改回原状态（不新建任务）。
- **理由**：列表行 hover 按钮容易误点；重建一条循环任务成本远高于撤销。5 秒是 Gmail 验证过的常用窗口。
- **不做**：删除的二次确认弹窗保留（彻底删除仍要确认），两者不冲突。

## UX-03 行内操作只放三个按钮

- **决策**：hover 显示 `📎 置顶` / `⏸ 暂停` / `⋯ 更多`；「更多」菜单固定 5 项：编辑、复制、立即提醒一次、删除（红色）、查看历史。
- **理由**：>=4 个行内图标会让列表视觉噪音大；把低频操作收进菜单。删除放菜单最后并用红色，降低误触。
- **不做**：拖拽排序（v1 用优先级 + 置顶已能表达顺序）。

## UX-04 首次使用给 3 张示例卡，而不是空白页

- **决策**：首次打开无任务时显示 3 张可点击的示例卡（工作日提醒 / 月末提醒 / 单次起止），点一下即创建；之后空态只显示「新建任务」。
- **理由**：空白页让新用户不知道「循环规则」怎么配；示例卡是最低成本的教程。示例任务都是真实任务，不是假数据。
- **不做**：多步引导 wizard（对个人工具过重）。

## UX-05 免打扰默认关闭，预设 22:00–08:00

- **决策**：`dnd.enabled=false` 默认关闭；开启后默认时段 22:00–08:00、可选「仅工作日」；**v1 不做任务级覆盖**（留 v1.1）。
- **理由**：默认开启会在第一天就静音掉早间提醒，用户会以为插件坏了。默认关 + 设置页一键开，符合「默认可用」。
- **边界**：DND 内到点的任务进「待展示队列」，DND 结束后合并为一条摘要；**若 DND 超过 12 小时或跨过整个白天，则不补弹、标 `missed`**，避免一次性弹几十条。

## UX-06 提醒提前量只做「一个」，且取代正点

- **决策**：每任务一个 `advanceMinutes`（0–1440，默认 0）；提前提醒**取代**正点提醒，不叠加两次。
- **理由**：用户要的是「提前知道」，不是「提前一次 + 准点一次」；两次提醒会被当成重复 bug。多档（提前一天 + 提前一小时）留 v1.1。

## UX-07 稍后提醒用预设 + 自定义输入

- **决策**：`5 分钟 / 15 分钟 / 1 小时` 三个预设按钮 + 「自定义」输入 1–1440 分钟；snooze 持久化，重启仍有效。
- **理由**：三个预设覆盖 90% 场景；自定义用数字输入而非下拉，少一次点击。

## UX-08 多窗口去重以服务端为准

- **决策**：以插件持久化的 occurrence 状态（`deliveredAt` / `readAt` / `ignoredAt`）为准；多窗口用 `BroadcastChannel` 做展示层同步（一个窗口 ack，其他窗口立即移除卡片）。
- **理由**：localStorage 方案在换浏览器/清缓存后失效；服务端状态是唯一真相。BroadcastChannel 是纯优化，不可用时靠轮询兜底。

## UX-09 时区：默认跟随原稿，任务级可改

- **决策**：全局默认 `Asia/Shanghai`（原稿要求）；每条任务可单独设置 IANA 时区；修改全局时区只影响新任务。
- **理由**：综合管理岗基本在国内，默认值正确；出差/跨区场景用任务级覆盖。不跟随浏览器时区（同一任务在不同设备会漂移，不可接受）。

## UX-10 提醒内容：4 个变量、纯文本

- **决策**：模板变量固定 `{title}` / `{time}` / `{note}` / `{phase}`；纯文本渲染、HTML 转义、不支持 Markdown；操作按钮由 UI 固定提供。
- **理由**：变量多了用户记不住；Markdown 在浮层里渲染不一致且是 XSS 面。四个变量覆盖「谁、什么时候、什么事、哪个节点」。

## UX-11 历史记录只保留 90 天，但「已完成」永久

- **决策**：`deliveries`（投递/错过记录）保留最近 1000 条或 90 天，取先到者；**已完成任务本身永久保存**（主文件本季度 + 季度归档）。
- **理由**：历史记录用于排障，90 天足够；已完成任务是用户资产，不能删。两者是不同的东西，容易混淆，故显式区分。

## UX-12 通知权限：首次勾选系统通知时才请求

- **决策**：默认只开浮层；用户在任务或设置里勾选「系统通知」时才调 `Notification.requestPermission()`；被拒绝后不再自动弹，设置页提供「重新请求权限」。
- **理由**：一进插件就弹权限框，用户大概率点拒绝，之后再也开不了。按需请求的通过率高得多。

## UX-13 不做「立即提醒一次」以外的批量操作

- **决策**：v1 不做批量暂停/删除/改时区（原 F4.8 降为 P2）。但「更多」菜单保留「立即提醒一次」，方便用户验证规则配对了没有。
- **理由**：个人待办一次操作 1–3 条，批量操作是给几十条场景设计的；「立即提醒一次」是验证规则的高频刚需。

## UX-14 搜索覆盖本季度 + 归档，结果带季度标签

- **决策**：全局搜索同时查 `tasks.json` 与 `archive/*.json`；归档命中项在结果里带「2026-Q3」标签，点击跳到归档视图。
- **理由**：用户记不住任务是哪个季度的；只搜当前季度会让人以为任务丢了。

## UX-15 错误态一律给「下一步动作」

- **决策**：所有错误提示必须带一个可执行动作，不允许只显示错误码。例如：
  - 数据文件损坏 → 「已备份并重建，去查看备份」
  - 通知权限被拒 → 「去设置里重新授权」
  - 保存失败（磁盘满）→ 「重试」
  - 归档季度不存在 → 「回到本季度」
- **理由**：只显示错误的界面等于让用户自己 debug。

## UX-16 提醒声音默认关闭，只提供内置音

- **决策**：`notify.sound=false` 默认关闭；开启后播放一次内置提示音；不提供自定义音频上传（v1.1 再说）。
- **理由**：默认响铃在办公场景很打扰；自定义音频涉及文件格式/解码/存储，v1 不值得。

## UX-17 不做深色模式单独设置

- **决策**：跟随 DSH 主题（`data-ds-dark-theme`），插件不提供自己的深浅色开关。
- **理由**：插件内再设一个主题开关会出现「DSH 浅色 + 插件深色」的割裂。跟随宿主是唯一正确解。

## UX-18 键盘可达但不用全局快捷键

- **决策**：列表页支持 `N`（新建）、`/`（搜索）、`Esc`（关闭）、`↑/↓`（移动）、`Enter`（打开）、`Space`（完成）；**不注册全局快捷键**（会与 DSH 冲突）。
- **理由**：全局快捷键需要宿主分配，且容易抢焦点；页面内快捷键已够用。

## UX-19 列表分组超过五条折叠

- **决策**：列表按「置顶 / 高 / 中 / 低 / 无 / 已暂停」分组后，**每个分组默认最多展示 5 条**；超过时底部显示「展开剩余 N 条」，点击展开全部，再次点击「收起」。搜索结果、已完成归档列表同样适用。
- **理由**：第三轮 180+ 条数据下，30 条/组会让用户滚动很久；先看每组前 5 条，能更快判断优先级，再主动展开细节。
- **状态**：展开/收起状态随当前分组组件保留；切换页签/搜索条件时重置为收起，避免上一次展开状态造成列表突然变长。
- **例外**：分组本身 ≤5 条时不显示折叠按钮。

## UX-20 完成按钮必须可识别

- **决策**：任务行左侧圆形按钮内默认显示浅色 `✓`，hover/focus 时变为业务主色并显示 `title="完成"`；`aria-label` 保持「完成」。用户不需要先 hover 才能知道它是完成按钮。
- **理由**：第三轮试用中空圆圈看起来像装饰/单选，用户不知道点击会完成任务；完成是最高频动作之一，必须一眼可识别。
- **代价**：行首视觉略增，但比增加文字「完成」按钮更紧凑。

---

## UX-21 更多菜单提供置顶入口

- **决策**：「⋯ 更多」菜单增加「置顶 / 取消置顶」项；行内 hover 的 📌 按钮保留，作为快速操作。用户从菜单用一次后，就知道行内按钮是同一动作的快捷入口。
- **理由**：置顶按钮 hover 才出现，静态页面不容易发现；菜单入口是稳定、可读的兜底路径，同时不牺牲行内快速操作。
- **不选**：把置顶按钮常驻到每行右侧会导致列表视觉噪音过大；菜单是低频入口，更适合作为发现路径。

---

## UX-22 自然语言输入使用弹窗

- **决策**：点击「✨ 自然语言新建」打开模态弹窗，弹窗内使用多行 `textarea`（至少 6 行 / 160px）；提供「解析」「取消」，支持 `Ctrl/⌘ + Enter` 提交。解析成功后关闭弹窗并打开编辑器；解析失败/降级同样关闭弹窗，由编辑器显示降级提示。
- **理由**：单行输入框只能显示一小段文字，用户描述复杂任务时看不到全文；弹窗给足输入空间，同时保持“只预填、不自动创建”的 F10.2 边界。
- **不做**：不在弹窗内直接创建任务；不在输入过程中调用模型（仍由「解析」触发）。

---

## UX-23 自然语言关闭态也保留入口

- **决策**：`settings.nlp.enabled=false` 时，工具栏仍显示「✨ 自然语言新建（设置中开启）」灰态按钮；点击打开设置弹窗。开启后恢复正常入口。
- **理由**：默认关闭是隐私选择，但完全隐藏入口会让新用户不知道功能存在；保留可见的关闭态入口，既不影响默认不联网，也提供了明确发现路径。
- **不做**：不在关闭态点击时直接开启模型调用；仍要求用户进入设置明确开启。

---

## UX-24 模型调用前明确提示

- **决策**：自然语言输入弹窗内显示模型调用说明：「点击解析会将输入文本发送给配置的模型服务；不发送任务库、设置或历史记录。」设置里的开关文案也保留同样说明。
- **理由**：自然语言功能默认关闭是隐私选择；开启后仍应在每次输入弹窗里让用户知道点击「解析」会调用模型，避免误以为纯本地处理。
- **不做**：不把提示做成阻塞确认弹窗；提示只需可读可见，不增加每次解析的点击负担。

---

## UX-25 系统通知权限状态可见

- **决策**：任务编辑器的「系统通知（页面不可见时）」选项下方显示浏览器通知权限状态：已授权、未授权（勾选并保存时会请求）、已拒绝（去浏览器设置恢复）、不支持（仅浮层）。
- **理由**：系统通知是默认关闭的可选能力，用户创建任务时不一定知道浏览器需要授权；显示状态并解释触发时机，比自动弹权限更可控，也避免用户误以为系统通知已生效。
- **不做**：不在打开编辑器时自动请求权限；不在用户未勾选系统通知时触发浏览器授权。

---

## UX-26 系统通知提供测试入口

- **决策**：任务编辑器在系统通知权限状态旁提供「测试系统通知」按钮；点击后才请求权限并发送一条测试通知。投递回执以浏览器 `onshow`/`onerror` 事件为准，没有事件则 3 秒后标记失败。
- **理由**：用户无法从界面判断系统通知是否真的会显示；测试按钮能把「浏览器已授权」和「系统实际展示」区分开，也便于排查 macOS/Electron 通知设置。
- **不做**：不在打开任务编辑器时自动发测试通知；不在用户未点击时请求权限。

---

## UX-27 系统通知权限按平台引导

- **决策**：系统通知选项下方按运行平台显示权限配置路径：macOS 为「系统设置 → 通知 → DeepSeek Harness」；Windows 为「设置 → 系统 → 通知 → DeepSeek Harness」；其他平台给出通用说明。任务编辑器与设置页一致。
- **理由**：用户已经勾选系统通知但收不到提示时，最常见原因是操作系统没有给 DeepSeek Harness 通知权限；不同平台设置路径不同，必须在产品内直接告诉用户，而不是让用户自己猜。
- **不做**：不尝试自动修改系统权限；只显示路径和测试入口，由用户自行授权。

---

## UX-28 最小化/失焦也视为后台

- **决策**：系统通知的后台判定使用 `document.visibilityState === 'hidden' || document.hasFocus() === false`，并在 `window` 的 `blur`/`focus` 事件上触发一次补偿轮询；不能只依赖 `visibilityState`。
- **理由**：Electron/WebView 在 macOS 最小化后可能仍报告 `visible`，导致用户勾选了系统通知却只看到浮层；`hasFocus()` 是桌面端更可靠的前后台信号。
- **不做**：不在页面可见且窗口聚焦时发送系统通知，避免和浮层重复打扰。

---

## UX-29 快捷功能说明入口

- **决策**：主面板顶部 header 提供「快捷功能说明」按钮；点击打开 Modal，介绍自然语言新建与系统通知及 macOS/Windows 权限路径；底部提供「去设置 / 关闭」。不把说明卡直接放在任务列表上。
- **理由**：入口固定、随时可查，不占用任务列表空间；用户不会把说明卡误认为任务或固定区域，视觉也更干净。
- **不做**：不做强制新手引导；不在任务列表中插入提示卡。

## 仍需用户拍板（不属于 UX，属于产品/资源）

| 编号 | 问题 | 为什么 UX 定不了 |
|---|---|---|
| 待定-1 | 归档文件永久保留还是 N 年后清理 | 涉及磁盘长期占用与用户对「永久」的预期；个人待办每年约 1–2MB，我倾向永久，但需你确认 |
