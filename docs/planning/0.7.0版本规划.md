# 0.7.0 版本规划与需求设计：桌面系统通知全局开关

> 当前基线：`0.6.0`（848 tests）
> 本轮版本：**`0.7.0`（已实现：851 tests）**
> 主题：**桌面系统通知从「任务级选项」改为「设置级一次性开关」**
> 目标：默认关闭；用户开启一次后全局生效；任务编辑器不再让用户配置系统通知。
> 评审：已按 [round5 评审意见](../reviews/round5/评审-0.7.0版本规划.md) R01–R15 修订
> 关联：[需求-v1](../requirements/需求-v1.md) v1.20、[UX-决策记录](../decisions/UX-决策记录.md) UX-30

## 1. 背景与结论

0.6.0 中系统通知是任务级字段：

```text
Task.notify.channels = ['overlay', 'system']
```

带来的问题：

- 用户需要理解每个任务的「系统通知（页面不可见时）」；
- 同一个用户对不同任务重复配置同一件事；
- 系统通知本质是设备权限，不是任务属性；
- 新用户容易漏配，或以为勾选一次就全局生效。

**决策：0.7.0 改为全局开关。**

- `settings.desktopNotifications.enabled`：默认 `false`；
- 开启后所有任务在后台/最小化时统一发送桌面系统通知；
- 任务编辑器不再显示系统通知复选框；
- 浮层始终保留，桌面通知只是后台补充。

### 2.2 行为要求（同版本必须）

- 开关打开时请求浏览器/系统通知权限；拒绝/不支持则保持 `false` 并显示可操作提示；
- 开关关闭时立即停止所有桌面通知，浮层不受影响；
- 旧任务 `notify.channels` 继续保留但不参与桌面通知判断（兼容，不丢数据）；
- 旧版本 0.6.0 读取 v4 文件时进入 `unsupported-version`/只读，不得静默丢失新设置。

### 2.3 不做（0.7.0）

- 不做任务级桌面通知 opt-out（后续按需评估）；
- 不做多设备/账号同步；
- 不改变 `CompletionEvent`、`/reports` 契约；
- 批量/模板、日历/ICS、任务级 DND、提醒升级留 `0.8.0`。

## 3. 数据设计

### 3.1 Settings

```ts
interface Settings {
  // existing...
  defaultChannels: Channel[]          // 兼容保留；system 不再由任务级编辑
  desktopNotifications: {
    enabled: boolean                  // default false
  }
}
```

- `desktopNotifications` 为**可选字段**，coerce 缺失时补 `{ enabled: false }`；
- **schemaVersion 3 → 4**：v3 文件迁移时补该字段，不改变任务结构；
- `defaultChannels` 保留用于旧数据/旧 API 兼容，但设置 UI 不再暴露 system 多选；
- 新任务 `notify.channels` 固定为 `['overlay']`；旧任务中的 `system` 保留但被全局开关覆盖；
- 旧版本读取 v4 文件必须拒绝（`unsupported-version`），避免旧版本写回时丢失全局设置。

### 3.2 生效规则

```text
effectiveChannels =
  ['overlay'] + (
    settings.desktopNotifications.enabled === true
      ? ['system']
      : []
  )
```

- 浮层永远发送；
- 桌面系统通知只有在：
  - 全局开关开启；
  - `Notification.permission === 'granted'`；
  - DSH 窗口后台/失焦（`visibilityState === 'hidden' || !document.hasFocus()`）；
  - 任务有当前 occurrence；
  时发送；
- `Task.notify.channels` 不再作为桌面通知开关；旧值仅兼容读取。

## 4. API 与宿主

- `GET /settings/get` 返回 `settings.desktopNotifications`；
- `POST /settings/update` 接受 `{ desktopNotifications: { enabled: boolean } }`（**不新增 PATCH**）；
- 校验：非 boolean → `invalid_argument`；
- **唯一 effective channel 来源**：宿主 `buildReminderCard(task, occurrence, settings)` 与 `deliveryRecordsFor(..., settings)` 使用同一份 `effectiveChannels`；
- `/due` 卡片携带 effective channels；客户端只按卡片字段决定是否发系统通知；
- 任务级 `notify.channels` 仍可由旧 API 读取，但宿主不因它单独开启 system；
- 报告、NLP、任务状态机不变。

## 5. 客户端

### 5.1 设置弹窗

新增「桌面系统通知」区块：

- Switch：`桌面系统通知`，默认关闭；
- 状态：`未开启 / 已开启 / 浏览器未授权 / 已被系统拒绝 / 当前浏览器不支持`；
- 按钮：**测试桌面系统通知**；
- 平台引导：
  - macOS：系统设置 → 通知 → DeepSeek Harness
  - Windows：设置 → 系统 → 通知 → DeepSeek Harness
- 开关开启状态机：
  1. 用户点击开关（此时不提前持久化）；
  2. 请求浏览器权限；
  3. 授权成功 → 保存 `enabled=true`；
  4. 拒绝/不支持 → 保持 `false`，显示原因和系统设置路径；
  5. 用户点「取消」→ 不保存，回到原值；
  6. 权限后来被系统撤销 → `enabled` 可保持 true（用户意图），实际发送前再检查 permission，并显示状态；
  7. 全局开关关闭时，测试按钮仍可点（用于诊断权限），但不会改变 `enabled`。

### 5.2 任务编辑器

- 删除系统通知复选框、状态提示、测试按钮；
- 保留浮层提醒说明；
- 可显示一行弱提示：

> 桌面通知由「设置 → 桌面系统通知」统一控制。

### 5.3 快捷功能说明

- 系统通知条目改为：

> 🔔 桌面系统通知：在设置中开启一次，所有任务在 DSH 后台/最小化时都会提醒。

- 不再描述任务级勾选；
- 「去设置」直接打开设置。
