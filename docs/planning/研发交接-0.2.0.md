## 1. 本轮需求设计（冻结口径）

### 1.1 数据模型

```text
Task:
  id, title, description, kind(once|recurring), status(active|paused|done|archived),
  pinned, doneAt, rule | once, notify, state, createdAt, updatedAt, revision

OnceWindow:
  startAt?: ISO 8601（省略 = createdAt；startAtSource="created"）
  endAt: ISO 8601（必填，唯一截止时间）
  startAtSource: "explicit" | "created"
  timeZone: IANA

NotifySettings:
  channels, template, advanceMinutes, sound,
  endReminder: boolean（默认 true；仅 once 使用）

TaskState:
  lastFiredAt, lastOccurrenceKey,
  firedStart, firedEnd, firedStartAdvance, firedEndAdvance,
  missedStart, missedEnd, missedAt, missedCount,
  snoozeUntil, completedOccurrenceKey
  # fired 为只读派生，不落盘
```

删除 `Task.dueDate`；`endAt` 是单次任务唯一截止，循环任务以 `rule.time` 为当期截止。`phase` 只保留给 occurrence 节点（`start/end/advance`），任务阶段字段统一叫 `stage`。

### 1.2 阶段规则

| stage | 判定 |
|---|---|
| `notStarted` | `active && kind=once && now < startAt` |
| `inProgress` | `active && kind=once && startAt ≤ now < endAt` |
| `overdue` | `active && kind=once && now > endAt`（`endAt` 当秒仍算进行中） |
| `done` | `status=done`（仅单次任务可 done） |
| `paused` | `status=paused` |
| `recurring` | `active && kind=recurring`（循环中/待触发） |
| `archived` | `status=archived`（仅归档查询，不进统计） |

- 循环任务**永远不进入 `done`**；`complete` 只推进当前 occurrence。
- `endAt` 到点**不自动 done**；未完成保持 `active` → `overdue`。
- `notify.endReminder=false`（会议类）只排 `#start`，且必须显式 `startAt`；省略 `startAt` 时只排 `#end`。

### 1.3 视图与统计

四个阶段页签只覆盖单次任务：

- 未开始 / 进行中 / 已超期 / 已完成
- 循环任务：独立 `recurring` 筛选，不计入四阶段徽标
- 已暂停：独立筛选/折叠区，不混入任何阶段页签

`GET /snapshot` 返回：

```json
{
  "counts": { "notStarted": 3, "inProgress": 2, "overdue": 1, "done": 4, "paused": 1, "recurring": 3 },
  "byKind": { "once": 11, "recurring": 3 },
  "totalDone": 4,
  "serverTime": "...",
  "nextTransitionAt": "..."
}
```

- `counts` 全量、不受 `status/kind/q` 过滤影响；
- `byKind` = 全部非 archived 任务；
- `totalDone` = 主文件 done + archive/index 各季度 count（id 去重）；
- `prioritySummary` 排除 paused/done/archived。

### 1.4 优先级与刷新

- 单次按 `endAt`、循环按 `nextAt`：
  - `now > endAt` 或 `remainingMs ≤ 24h` → 高
  - `24h < remainingMs ≤ 72h` → 中
  - `72h < remainingMs ≤ 168h` → 低
  - `> 168h`/无目标 → 无
- `priority = { key, remainingMinutes }`，`remainingMinutes` 向下取整、不落盘。
- 取消每日 00:05 重算；读时派生；客户端按 `serverTime` + `nextTransitionAt` 刷新（兜底 60 秒）。
- 排序：`pinned → priority → endAt（循环 nextAt）→ title`。

### 1.5 API 与工具

- `/snapshot`：`view=notStarted|inProgress|overdue|done|recurring|paused`，默认 `inProgress`。
- `/tasks/create`：`once{startAt?,endAt,timeZone}`，不接受 `dueDate`。
- `/tasks/delete`：`{id,purge?,confirm?}`；`purge=true` 必须 `confirm:true`。
- `POST /tasks/remind`：立即提醒一次，不改规则/`fired`。
- `GET /deliveries`：查询投递/回执历史。
- 9 个 `todo_reminder_*` 工具；不要求 `exec.agent`（任务不绑定会话）。

### 1.6 迁移

`schemaVersion 1→2`，四条链路使用同一迁移函数：

1. `tasks.json`
2. `archive/completed-*.json`
3. `archive/index.json`
4. `POST /import`

规则：删除 `dueDate`；保留 `once.startAt` 并补 `startAtSource="explicit"`；补 `notify.endReminder=true` 与 TaskState 默认字段；旧单次任务缺 `endAt` → `migration-failed` 并保留原文件，不猜测映射。
