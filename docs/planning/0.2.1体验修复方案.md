# 0.2.1 体验修复方案（第二轮反馈）

> 来源：[第二轮体验问题评估](../reviews/round3/第二轮体验问题评估.md)
> 范围：0.2.x 客户端/工具小修；不改 D-25 数据模型、不改调度核心。
> 结论：**0.2.1 已实现 F7.14～F7.18 和 P2-H；本文件只剩客户端/UI 4 项、搜索口径 1 项，P2-G 延后。**

## 1. 要修改的问题与方案

### FIX-01（P1-B）筛选竞态：徽标有数、列表为空

**问题**
`src/client/panel.ts` 的 `load()` 直接 `setItems(snapshot.items)`。快速切换「循环任务/已暂停」或搜索时，旧请求可能晚于新请求返回并覆盖新结果，出现“徽标 2、列表空”。

**方案**
- 在 `panel.ts` 增加 `requestSeqRef = useRef(0)`；
- `load()` 开始时 `const seq = ++requestSeqRef.current`；
- 所有 `setItems/setCounts/setTotals/setNextTransitionAt/setSettings` 前判断 `seq === requestSeqRef.current`，否则丢弃；
- 切换 view/search 时先 `setPhase('loading')`，列表显示骨架屏，不显示“没有任务”空态；
- 可选 `AbortController`：把 `api.snapshot` 增加 `signal`，卸载/新请求时 abort。

**涉及文件**
`src/client/panel.ts`、`src/client/api.ts`（可选 signal）

**验收**
- 人为延迟旧请求（测试桩 300ms/50ms），快速切「循环任务」→ 只显示新结果；
- 切换期间显示骨架屏，不出现“没有循环任务”。

### FIX-02（P2-D）设置弹窗按钮文案

**问题**
`src/client/settings-modal.ts:67` 使用 `t('form.save')`，该 key 是「保存任务」，设置弹窗显示错误。

**方案**
- `dictionary-zh.ts` / `dictionary-en.ts` 新增：
  - `settings.save`: `保存设置` / `Save settings`
- `settings-modal.ts` 的 footer 保存按钮改用 `t('settings.save')`。

**验收**
- 打开设置弹窗，底部按钮为「保存设置」；任务编辑器仍为「保存任务」。

### FIX-03（P2-E）仅截止任务行显示开始时间

**问题**
`src/client/task-row.ts:40-45` 的 `ruleSummary()` 对 `once` 无条件拼 `startAt → endAt`；`startAtSource="created"` 的开始时间只是内部默认，用户没有填写，不应展示。

**方案**
- `ruleSummary()` 增加：
  ```ts
  const start = task.once.startAtSource === 'created'
    ? ''
    : formatInZone(task.once.startAt, zone)
  ```
- 若 `startAtSource === 'created'`，返回 `单次 · 截止 ${end}`；否则返回 `单次 · ${start} → ${end}`。
- 详情抽屉仍可展示 `startAtSource` 说明「创建时间（未设置开始）」。

**涉及文件**
`src/client/task-row.ts`、`src/client/task-editor.ts`（详情展示可选）

**验收**
- 不填开始时间创建任务，列表行只显示「单次 · 截止 2026-10-31 18:00」；
- 显式开始任务仍显示「单次 · 2026-10-31 14:00 → 18:00」。

### FIX-04（P2-C）字段级校验错误

**问题**
`task-editor.ts` 的 `save()` 只校验标题和起止顺序；未填 `endAt` 时直接请求后端，`invalid_argument` 被字典统一翻译成「参数不合法」，没有字段定位。

**方案**
- `task-editor.ts` 增加本地校验：
  - `kind=once && draft.endAt.trim()===''` → `setError(t('form.endAtRequired'))`，并把 `fieldErrors.endAt` 传给 `OnceFields`；
  - `kind=once && draft.startAt && draft.endAt && endAt<=startAt` → 现有 `form.endAfterStart`，对应字段标红；
- `editor-fields.ts` 的 `OnceFields` 接收 `fieldErrors?: { startAt?: string; endAt?: string }`，对应 input 加 `aria-invalid` + `.dtd-field-error`；
- 字典新增 `form.endAtRequired`: `结束时间为必填` / `End time is required`；
- 后端 `validateTime.ts` 的 `once.endAt is required` message 保留，用于 API/Agent 调用。

**涉及文件**
`src/client/task-editor.ts`、`src/client/editor-fields.ts`、`src/client/dictionary-*.ts`、`src/client/styles.ts`

**验收**
- 单次任务不填结束时间保存 → 结束时间输入框红框 + 「结束时间为必填」，不出现泛化「参数不合法」；
- 起止倒置 → 结束时间字段标红，提示「结束时间必须晚于开始时间」。

### FIX-05（P1-A）循环任务提前完成/跳过下一次

**问题**
`repo.complete()` 对 `kind=recurring` 要求 `lastOccurrenceKey` 非空；新建循环任务从未触发时点击行首「完成」→ `no_occurrence`，toast「当前没有可完成的提醒」。

**现状**
- 0.2.0 的后端/工具已经支持 `skipNext`：`repo.complete(..., skipNext)`、`/tasks/complete` 和 `todo_reminder_complete` 都已实现（F7.18）；
- **缺口只在客户端**：`src/client/api.ts` 的 `complete()` 不发送 `skipNext`，`src/client/panel.ts` 的 `onComplete` 也不判断“循环任务尚未触发”。

**方案**
- `src/client/api.ts` 的 `complete(id, occurrenceKey?, skipNext?)` 请求体增加 `skipNext`；
- `src/client/panel.ts` 的 `onComplete`：
  - 若 `task.kind === 'recurring' && task.state.lastOccurrenceKey === null`，调用 `api.complete(task.id, undefined, true)`；
  - 其他调用保持 `api.complete(task.id)`；
- `dictionary-*.ts` 增加 `toast.skippedNext`（如「已跳过下一次提醒」），用于该分支反馈；
- 后端 **不需要改**，补一条 UI 回归测试：新建循环任务未触发 → 点完成 → 成功且任务仍 active。

**验收**
- 新建循环任务，未触发时点击「完成」→ 成功 toast「已跳过下一次」；
- 下一次触发从再下一次开始；
- 循环任务状态仍 `active`，不进入 `done`；
- Agent `todo_reminder_complete({id,skipNext:true})` 同样成功。
