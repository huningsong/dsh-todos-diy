### 1.2 三条 P0 回归（原 0.1.0 问题）

| 编号 | 检查 | 操作 | 预期 |
|---|---|---|---|
| R-05 | `endAt` 即截止 | 创建 `once{startAt,endAt}`，不传 `dueDate` | `stage`/`priority` 由 `endAt` 派生；传 `dueDate` 返回 `invalid_argument` |
| R-06 | `startAt` 可省略 | 创建 `once{endAt}` | 成功；`startAt=createdAt`、`startAtSource="created"`；无 `#start` 投递 |
| R-07 | 逾期不自动完成 | 创建已过 `endAt` 的单次任务，等待一次 tick | `status=active`，`stage="overdue"`，`doneAt=null`；只有 `complete` 才 `done` |

### 1.3 状态、视图与统计

| 编号 | 检查 | 操作 | 预期 |
|---|---|---|---|
| R-08 | `stage` 边界 | `now == startAt` / `now == endAt` / `endAt+1s` | `notStarted → inProgress → overdue`（`endAt` 当秒仍 inProgress） |
| R-09 | 四阶段页签 | 构造 1 未开始 + 2 进行中 + 1 超期 + 4 完成 + 2 循环 + 1 暂停 | 四个页签 1/2/1/4；循环/暂停独立筛选；徽标一致 |
| R-10 | counts 全量 | 带 `status/kind/q` 过滤请求 `/snapshot` | `counts/byKind/totalDone` 不随过滤变化；`done` 为本季度主文件 |
| R-11 | 优先级边界 | `remainingMs = 24h/24h+1m/72h/72h+1m/168h/168h+1m/过期` | 依次为 `high / mid / mid / low / low / none / high`（`remainingMinutes` 向下取整） |
| R-12 | 不自动 done 的循环任务 | 新建循环任务后 `complete`（无 occurrence） | 若未实现 `skipNext`，应返回 `no_occurrence`；不得把循环任务置 `done` |

## 2. 需求设计修改方案

### 2.1 0.2.0：不修改产品模型，只补回归文件

不新增 F 需求。把 §1 的 R-01～R-16 写入：
- `docs/testing/测试记录.md` 的“R3/0.2.0 回归”；
- `docs/requirements/需求-v1.md` 附录新增“0.2.0 回归清单（执行记录）”；
- 已有 AC-06/07/29/31/32/35/40/41/42/43/44/45 逐条对照。

### 2.2 0.2.1：P1 体验与 Agent 能力补齐（冻结候选）

| 新需求 | 变更 | 验收口径 |
|---|---|---|
| **F7.14 `todo_reminder_get`** | 新增单条查询工具：`id` → `TaskView` | 返回同 `/tasks/get`；不存在 → `not_found`；Agent 可直接拿 `revision` 后 update |
| **F7.15 create 幂等** | `todo_reminder_create` / `POST /tasks/create` 增加 `idempotencyKey?`（16–128 字符）；同 key 重试返回已有任务并标 `replayed:true`；同 key 不同 payload → `conflict` | 网络超时重试不产生第二条任务/第二次提醒；同 key 二次调用只返回原任务 |
| **F7.16 list 默认与 all 视图** | 工具 `todo_reminder_list` 默认 `view="all"`（全部非 archived）；HTTP `/snapshot` 保持 UI 默认 `inProgress`；六枚举增加 `all` | Agent 问“我有哪些待办”时返回未开始/进行中/超期/循环/暂停/已完成全量并可分页 |
| **F7.17 remind/deliveries 工具** | 新增 `todo_reminder_remind(id)`、`todo_reminder_deliveries(taskId?,limit?,cursor?)`；复用已有 HTTP `/tasks/remind`、`/deliveries` | 返回 `occurrenceKey/deliveredAt` / `items,nextCursor,total`；不改变原规则与 `fired` |
| **F7.18 complete skipNext** | `todo_reminder_complete` 增加 `skipNext?: boolean`；对未触发的循环任务，按 `nextOccurrence(rule, now)` 生成跳过 key，写 `completedOccurrenceKey/lastOccurrenceKey`，不改 `status=done` | 新建循环任务直接 `complete({skipNext:true})` 成功，下一次触发从再下一次开始；不传 `skipNext` 仍返回 `no_occurrence` |

### 2.3 0.3.0 / v1.1：批量与场景增强

| 需求 | 内容 |
|---|---|
| F4.8 批量操作 | 批量暂停/恢复/删除/改提前量，单次 ≤200，逐条返回 `partial` |
| E08 任务模板 | 月度综合管理清单、周例会清单、合同到期清单；一键生成多条 |
| F5.6 任务级 DND | 任务级覆盖全局免打扰（可选） |
| E06/E09/E11 | 日历视图 / ICS 导出 / 提醒升级 |

### 2.4 明确不改 / 不跟踪

- `title` 200 字符：当前已强校验；
- `health.storage.path`：当前与实际文件一致；
- `dueDate` schema：当前 `rejectLegacyFields` 已拒绝；
- 多插件并存：当前 profile 只加载 `dsh-todos-diy`；旧数据目录仅做安装提示，不作为 0.2.0 代码需求。
