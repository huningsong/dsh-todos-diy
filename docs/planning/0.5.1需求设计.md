# 0.5.1 需求设计：搜索范围收口 + NLP 降级提示

> 基线：`0.5.0`（commit `456c99c`，799 tests）
> 版本：`0.5.1`（补丁版，不改数据模型、不改 `/reports`、不新增后端 API）
> 来源：[0.5.0 真实试用意见](../reviews/round4/工作待办-0.5.0-试用意见.md) 的 **P1-1 / P1-2**
> 范围：仅这两项；P2-1～P2-6 统一进 0.6.0「批量/体验批次」，不在本版实现。

## 1. 背景与问题

### 1.1 P1-1 搜索只在当前页签内生效

0.5.0 的 `panel.load(view, q)` 把当前 `view` 与搜索词一起发给 `/snapshot`。用户切到「已超期」页签搜索“预算”时返回空，而任务实际在「进行中」。placeholder 虽写着「在当前视图内搜索」，但综合管理岗不记得任务在哪个阶段，结果是**误判任务不存在**。

### 1.2 P1-2 NLP 降级没有任何提示

`POST /parse` 降级时返回 `degraded=true, reason=llm_unavailable|timeout|bad_output`。客户端 `NlpBar` 只把原文交给面板打开编辑器，降级提示 `hint` 留在被遮挡的输入条里；用户看到的是「原文成了标题、类型是单次、没有预填」，**不知道解析失败，也不知道可以重试**。

## 2. 版本定位与约束

- 补丁版 `0.5.1`：只改客户端交互，**不改** `Task`/`CompletionEvent`/`schemaVersion`/`/reports`/`/parse` 契约。
- 复用现有 `GET /snapshot?view=all&q=`（0.2.1 已有 `all` 视图），后端零改动。
- 复用现有 `POST /parse` 的 `degraded/reason` 字段，后端零改动。
- 客户端 `ViewName` 类型需增加 `'all'`（`api.snapshot` 参数类型），这是**客户端类型改动**，不是后端契约改动。
- 所有新增文案走 `dictionary-zh/en`，无硬编码中文；新增控件补 `aria-label`/`aria-pressed`/`role="status"`。
- 不引入新的全局状态库；搜索范围偏好存 `localStorage`（读写失败静默回退默认值）。

## 3. 需求 F8.17：搜索范围（P1）

> 编号说明：F8.16 已被「快捷键（UX 决策）」占用、F8.18 已被「完成按钮可识别」占用，本需求使用空缺的 **F8.17**。

### 3.1 行为定义

| 状态 | 行为 |
|---|---|
| 搜索框为空 | 保持当前页签视图（行为不变） |
| 搜索框非空 + 范围=全部任务（默认） | 请求 `view=all&q=<keyword>`，返回全部非归档任务中标题/说明匹配的项；页签保持原选择（不影响徽标） |
| 搜索框非空 + 范围=当前视图 | 请求 `view=<当前页签>&q=<keyword>`（0.5.0 行为） |
| 清空搜索 | 回到当前页签的普通列表 |
| 切换页签 | 搜索词与范围都保留；范围=当前视图时按新页签重查；范围=全部任务时结果不变（页签只改变普通列表的背景状态） |

### 3.2 搜索目标解析（唯一入口）

新增纯函数 `resolveSearchTarget(view, scope, query)`：

```ts
// 空 query → view；scope==='all' → 'all'；否则 → view
```

**所有** `load()` 调用（首次进入、切页签、搜索防抖、完成/保存/设置后的刷新、`nextTransitionAt` 定时刷新、`dsh-todos-diy:changed` 监听）都必须经过该函数，禁止任何路径直接传 `view` 或空 query 覆盖搜索。切页签 effect 不再显式传 `''`，改为 `load(view, search, true)`。

### 3.3 UI

- 搜索行右侧增加范围切换（分段按钮）：`全部任务` / `当前视图`，默认 `全部任务`；`localStorage` 键 `dsh-todos-diy.searchScope`（读失败用默认值，写失败忽略）。
- 占位文案随范围变化：全部任务「搜索全部任务」；当前视图「在当前视图内搜索」。
- 搜索非空时，列表上方显示结果条（`role="status"`）：
  - 全部任务：`在全部任务中搜索「预算」· 当前显示 3 条`
  - 当前视图：`在当前视图中搜索「预算」· 当前显示 1 条`
- 结果超过单页上限（200）时追加提示：`仅显示前 200 条，请补充关键词`；是否超限以 `nextCursor !== null` 判断，不能只用 `items.length === 200`。
- 空结果文案按范围区分：
  - 全部任务：`没有找到与「x」匹配的任务` + 「清除搜索」；
  - 当前视图：`当前视图没有匹配，试试在全部任务中搜索` + 「在全部任务中搜索」按钮（一键切范围）。
- 搜索不改变四阶段徽标 `counts`、`byKind`、`totalDone`（仍为全量）。

### 3.4 与现有视图的交互

- **「已完成」页签**：0.5.0 在 `view==='done'` 时渲染归档视图（`ArchiveView`）。搜索激活（query 非空）时必须**强制渲染普通结果列表**（`TaskList` 的搜索分支），不得落入归档视图；清空搜索后恢复归档视图。F8.11 的验收口径补一句「搜索态例外」。
- **阶段标识**：搜索范围=全部任务时，结果行必须显示**阶段徽标**（未开始/进行中/已超期/已完成/循环/已暂停），复用 `tab.*` / `filter.*` 文案；当前视图范围不显示（用户已知）。阶段徽标放在优先级徽标之后、类型徽标之前。
- **行操作矩阵**（`TaskRow` 新增 `canComplete`/`canPause` 计算，搜索态与普通态共用）：
  | 任务状态/阶段 | 完成按钮 | 暂停/恢复 | 置顶 | 编辑/复制/历史/删除 |
  |---|---|---|---|---|
  | active（未开始/进行中/已超期） | 可用 | 可用（暂停） | 可用 | 可用 |
  | paused | 禁用 | 可用（恢复） | 可用 | 可用 |
  | done / archived | 禁用 | 禁用 | 禁用 | 可用（历史/删除；归档走恢复入口） |
  搜索态下，已完成/已暂停任务的无效按钮隐藏或禁用；更多菜单只保留与状态匹配的项。
- **列表折叠（F8.9）**：搜索结果同样适用每组 5 条折叠；切换关键词时折叠状态重置为收起。
- **空白关键词**：`query.trim()===''` 按“无搜索”处理（不进入搜索态、不显示结果条）。
- **独立筛选高亮**：搜索范围=全部任务时，`循环任务`/`已暂停` 两个 chip 取消高亮（结果跨筛选）；范围=当前视图时保持原高亮。
- **竞态**：沿用 FIX-01 的 `requestSeqRef`/`AbortController`，快速改关键词只接受最后一次结果。
- **分页**：搜索请求使用 `limit=200`；结果条显示「当前显示 n 条」，不承诺超出 200 的真实总数（提示补充关键词）。

### 3.5 验收 AC-59

1. 切到「已超期」页签，搜索“预算” → 出现「Q4 预算申报」；该行显示「进行中」阶段徽标；结果条显示「在全部任务中搜索」。
2. 结果条「当前显示 n 条」= `/snapshot?view=all&q=预算&limit=200` 的 items 数；且 n ≥ 当前页签视图的匹配数。
3. 切范围到「当前视图」→ 同一关键词结果变为该页签内的匹配（可为空），空态出现「在全部任务中搜索」按钮。
4. 清空搜索 → 回到原页签普通列表，四阶段徽标与 `totalDone` 不变。
5. 搜索期间四阶段徽标与 `totalDone` 不随关键词变化。
6. 在「已完成」页签搜索 → 显示普通结果列表（不是归档季度视图）；清空后恢复归档视图。
7. 快速连续输入关键词（防抖内）→ 最终列表只对应最后一个关键词，无旧结果覆盖。
8. 点击「在全部任务中搜索」→ 范围切到全部任务并立即重查。

## 4. 需求 F10.11：NLP 降级提示（P1）

### 4.1 行为定义

- `NlpBar` 解析返回 `degraded=true` 时：
  1. 输入条保留原文与降级原因（关闭编辑器后仍能看到）；
  2. 打开编辑器时带 `degraded` 上下文：`{ text, reason }`（统一用 `text`，不再使用 `originalText`）；
  3. 编辑器顶部显示**警告样式横幅**（`role="alert"`）：
     - 主文案：`自动解析暂不可用，已保留原文，请手动补充`
     - 原因行：按 `reason` 映射——`llm_unavailable`「模型服务不可用（未配置或连接失败）」；`timeout`「模型响应超时（8 秒）」；`bad_output`「模型返回内容无法解析」；未知 reason 回退通用「模型服务暂时不可用」
     - 操作：`重试解析` 按钮 + `关闭提示`（仅隐藏当前编辑器的横幅，不关闭编辑器）
  4. 标题保留原文（≤200 字），其余字段为空/默认；
  5. 解析永不返回 5xx（沿用 0.5.0）。
- 重试：
  - 点击「重试解析」→ 再次调用 `/parse`（同一 `text`，带 `AbortSignal`）；
  - 成功：用解析结果覆盖**未被用户修改**的字段，并更新 `fieldStatus`/`missingRequired`（详见 §4.4）；
  - 再次降级：横幅更新原因，不重复插入文字、不重置用户已改字段；
  - 重试期间按钮显示「解析中…」并禁用；
  - 重试抛 `ApiError`：横幅显示错误文案（`error.*` 字典），保留「重试解析」；
  - 重试中关闭编辑器/按 Escape/点遮罩：abort 请求，结果不写回已卸载组件。
- **状态归属（单一 owner）**：降级上下文**与输入条提示**都由 `Panel` 持有：
  - `degradedSource: { text, reason } | null`
  - `nlpHint: string | null`（输入条上的「自动解析不可用…」提示，受控 prop 传给 `NlpBar`）
  `NlpBar` 不保留 degraded 的局部 hint（API 网络错误可局部提示），只负责发起解析并上报；`TaskEditor` 是受控展示 + 重试回调，不自行维护全局降级状态。
- 清除条件：编辑器内重试成功（`onDegradedSuccess`）、保存成功、或重新发起一次成功解析时，同时清空 `Panel.degradedSource` 与 `Panel.nlpHint`；关闭编辑器不清空（输入条仍可见原文与原因），再次从输入条打开会重新显示横幅。
- **banner 优先级**：`degraded` 横幅存在时替代普通 `banner`（`nlp.banner`/`nlp.missing` 不叠加显示）；普通解析（未降级）路径行为与 0.5.0 完全一致。

### 4.2 数据与契约

- `/parse` 实际 degraded reason 仅三种：`llm_unavailable`（无模型/连接失败）、`timeout`（8s）、`bad_output`（非 JSON）。`nlp_disabled` 是 **409 错误码**，不走 degraded 分支；`NlpBar` 只在 `settings.nlp.enabled === true` 时渲染。
- 客户端新增类型（与 `api.ts` 现有 `NlpParsePayload` 对齐，避免同名不同型）：
  ```ts
  type NlpDegradedReason = 'llm_unavailable' | 'timeout' | 'bad_output' | 'unknown'
  interface NlpDegradedContext { text: string; reason: NlpDegradedReason }
  ```
- 编辑器新增 props：
  - `degraded?: NlpDegradedContext`
  - `onRetryParse?: (text: string, signal: AbortSignal) => Promise<NlpParsePayload>`（由 Panel 注入；返回 `api.parse` 的 `NlpParsePayload`，**不是** host 的 `NlpParseResult`）
  - `onDegradedSuccess?: () => void`
- `api.parse(text, signal?: AbortSignal)` 增加可选 signal；`TaskEditor` 在重试开始时创建 `AbortController`，在关闭/Escape/遮罩/卸载时 abort，结果不写回。
- 重试用 `api.parse(text, signal)`；成功后 `draftFromParse` + `mergeParsedDraft`。
- 新增 i18n key（中英文都要有，`{query}`/`{n}` 参数）：
  - `nlp.degraded.title`、`nlp.degraded.reason.llm_unavailable`、`nlp.degraded.reason.timeout`、`nlp.degraded.reason.bad_output`、`nlp.degraded.reason.unknown`
  - `nlp.degraded.retry`、`nlp.degraded.retrying`、`nlp.degraded.dismiss`
  - `nlp.searchScope.all`、`nlp.searchScope.view`、`nlp.searchResult.all`（{query,n}）、`nlp.searchResult.view`（{query,n}）、`nlp.searchEmpty.all`（{query}）、`nlp.searchEmpty.view`（{query}）、`nlp.searchAll`、`nlp.searchLimit`
  - `search.placeholderAll`、`search.placeholderView`（替换原 `panel.searchPlaceholder`，兼容旧 key 删除并更新 `test/d021-ui.test.ts` 的 P2-F 断言）

### 4.3 状态机

| 当前状态 | 事件 | 下一状态 | 行为 |
|---|---|---|---|
| idle | 提交解析 | parsing | 按钮「解析中…」 |
| parsing | 成功 | success | 打开编辑器（普通横幅）；清空上次降级上下文 |
| parsing | degraded | degraded | 打开编辑器 + 警告横幅；输入条保留原文+原因 |
| degraded | 点「重试解析」 | retrying | 按钮禁用，横幅显示解析中 |
| retrying | 成功 | success | 按 §4.4 合并；横幅消失；`onDegradedSuccess` 清空 NlpBar hint |
| retrying | 再次 degraded | degraded | 横幅更新原因；用户已改字段保留 |
| retrying | ApiError | degraded | 横幅显示错误文案，保留重试入口 |
| degraded | 点「关闭提示」 | degraded-dismissed | 仅隐藏当前编辑器横幅；保存不受影响；从输入条再打开重新显示 |
| degraded | 关闭编辑器 | degraded-closed | 输入条保留原文+原因；再次解析按新请求处理 |
| retrying | 关闭编辑器/Escape/遮罩 | closed | abort 请求；不写回 |

### 4.4 `mergeParsedDraft(current, parsed, initial)` 算法

- **比较**：数组字段（`weekdays`、`monthDays`、`skipDates`、`extraWorkdays`、`channels`）按**深度比较**；`startAtSource` 特殊处理（用户未改时沿用 parsed 的 `startAtSource`）。
- **覆盖规则**：`current[k]` 与 `initial[k]` 深度相等（或均为空数组）→ 用 `parsed[k]`；不等 → 保留 `current[k]`。
- **kind 切换**：若用户手动改过 `kind`（`current.kind !== initial.kind`），保留用户的 kind，仅合并与 kind 无关的字段（title 已改则保留、description、channels、advanceMinutes、sound、template）；不合并规则/窗口字段。
- **fieldStatus**：合并后，被用户保留的字段标记为 `explicit`（不显示「需补充」）；其余字段沿用 parsed 的 `fieldStatus`。
- **missingRequired 重算**（合并后，按 preset 精确）：
  | 条件 | 追加字段 |
  |---|---|
  | `title.trim()===''` | `title` |
  | `kind==='once'` 且 `endAt.trim()===''` | `endAt` |
  | `kind==='recurring'` 且 `preset==='workdays'` 且 `time` 非法 | `time` |
  | `kind==='recurring'` 且 `preset==='weekly'` 且（`time` 非法或 `weekdays.length===0`） | `time` / `weekdays` |
  | `kind==='recurring'` 且 `preset==='monthly'` 且（`time` 非法或 `monthDays.length===0`） | `time` / `monthDays` |
  | `kind==='recurring'` 且 `preset==='custom'` 且 `cron` 非法 | `cron` |
  重算结果用于 `TaskEditor` 的 `nlp.missing` 横幅（`banner` 文案由 Panel 依据 `missingRequired` 生成）。
- 纯函数、无 React，可单测数组/kind/用户已填字段三类用例。

### 4.5 验收 AC-60

1. **单测（fake LLM）** 覆盖四种降级来源：无模型（`llm_unavailable`）、超时 8s（`timeout`）、非 JSON（`bad_output`）、未知 reason（回退通用文案）；`POST /parse` 均无 5xx。
2. **UI 冒烟（真实页面）**：临时 profile 无模型 → 输入一句话 → 编辑器出现警告横幅（含原因、重试、关闭）+ 标题原文；无未翻译 key。
3. **重试成功**：用可注入 fake LLM 的路由/组件测试重试成功 → 表单被解析结果填充、横幅消失、字段三态徽标出现。
4. **字段保留**：`mergeParsedDraft` 单测——用户改「说明」后重试成功，说明保留；用户改 `kind` 后不合并规则字段；数组深比较正确。
5. **关闭/重开**：关闭横幅后可保存；从 NlpBar 再次打开重新显示；关闭编辑器后输入条仍有原文与原因。
6. **重试异常**：重试抛 `ApiError('network_error')` → 横幅显示本地化错误，重试按钮可用；快速连点只发一次请求；重试中关闭编辑器不写回。
7. **回归**：普通解析仍显示 `nlp.banner`/`nlp.missing`；`nlp_disabled` 409 走错误提示不开编辑器；F11 报告测试全过。

## 6. 测试计划

- **真实页面（ego-browser）**：

  4. 「已完成」页签搜索 → 普通结果列表；清空 → 归档视图。
