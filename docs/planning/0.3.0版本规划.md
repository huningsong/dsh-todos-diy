# 0.3.0 版本规划与需求设计：周报 / 月报

> 当前代码基线：`0.2.1`（D-25 + Agent 体验补齐）
> 下一版本：**`0.3.0`**
> 主要目标：**一键生成周报 / 月报**，并补齐循环任务完成历史的数据基础
> 需求版本：v1.5（相对 v1.4 新增 F11）
> 关联：[周报月报评估](../requirements/评估-周报月报.md)、[需求-v1](../requirements/需求-v1.md)、[缺口清单 E03](../decisions/待讨论-缺口清单.md)

## 1. 版本定位

0.2.1 已经具备：

- D-25 的 `stage` / `endAt` / 六视图 / counts；
- 单次任务 `doneAt` 与季度归档；
- 9→12 个 Agent 工具（get / remind / deliveries / skipNext）。

0.3.0 不改变任务状态机，只做**围绕“回顾与汇报”的报告层**：

- 周报 / 月报是**只读派生**，不落盘、不改变任务；
- 报告默认用确定性 Markdown 模板，不调用 LLM；
- 先补循环任务完成事件日志，确保报告数据可信。

## 3. 数据设计

### 3.1 CompletionEvent（schema v3）

```ts
interface CompletionEvent {
  id: string                    // uuid
  taskId: string
  taskTitle: string             // 快照，任务删除后仍可报告
  kind: 'once' | 'recurring'
  occurrenceKey: string
  completedAt: string            // ISO
  dueAt: string | null           // once.endAt / recurring occurrence 时间
  timeZone: string
}

interface PersistedState {
  schemaVersion: 3
  ...
  completionEvents: CompletionEvent[]
}
```

规则：

- `repo.complete` 成功后追加一条事件；
- 单次任务仍保留 `doneAt`，报告优先用事件，缺失时回退 `doneAt`；
- 循环任务必须有事件才能统计历史完成次数；
- 保留最近 **5000 条**（或 24 个月，先到先裁剪），避免主文件无限增长；
- 迁移 `v2 → v3`：补 `completionEvents: []`；历史单次可从 `doneAt` 回填（可选），历史循环不可回填；
- 归档文件中的任务不需要改写 schema，报告读取任务时按 `doneAt` 统计。

### 3.2 ReportData

```ts
interface ReportData {
  period: {
    kind: 'weekly' | 'monthly'
    start: string
    end: string
    timeZone: string
  }
  completed: ReportItem[]       // 单次 doneAt / 循环 CompletionEvent
  overdue: ReportItem[]        // 当前 active 单次 endAt < now
  created: ReportItem[]        // createdAt ∈ period
  upcoming: ReportItem[]       // nextAt/endAt ∈ next period
  stats: {
    completed: number
    overdue: number
    inProgress: number
    recurring: number
    completionRate: number | null
  }
  generatedAt: string
}
```

说明：

- `completed` 单次按`doneAt`；循环按`CompletionEvent.completedAt`；
- 全部使用报告时区的周期边界；任务自身时区只影响任务时间展示，不改变聚合边界；
- 逾期/新增/下周期计划均排除 archived；完成项包含已归档任务；
- 报告接口只读，不调用 `touch()`/不修改 `tasks.json`。

## 4. API 设计

```http
GET /api/dsh-todos-diy/reports?kind=weekly&anchor=2026-10-30
GET /api/dsh-todos-diy/reports?kind=monthly&anchor=2026-10-30
```

- `anchor`：周期内任意一天，服务端换算成周/月边界；
- 错误：`invalid_argument`（kind/anchor 非法）、`storage_error`；
- 鉴权：与其他 exact 路由一致，委托 `connection.requestRejection`；
- 返回 `{ ok: true, value: ReportData }`；
- 可选 `?include=...` 不进入 MVP。

## 5. 客户端设计

- `PanelHeader` 增加「生成报告」按钮（与「设置 / 新建任务」同排，次级样式）；
- 新组件 `ReportModal`：
  - 顶部 Tab：周报 / 月报
  - 周期选择：本周 / 上周 / 本月 / 上月
  - Markdown 预览区域（等宽字体、可滚动）
  - 底部：复制 Markdown / 导出 `.md` / 关闭
- 复制失败提示「复制失败，请手动选择文本」；
- 导出文件名：`工作周报-YYYY-MM-DD.md` / `工作月报-YYYY-MM.md`；
- 不改现有 `main` slot/路由；纯客户端组件。

## 6. 报告模板

```markdown
# 工作周报（2026-10-26 ~ 2026-11-01）

## 本周完成（3）
- [x] 供应商合同评审
- [x] Q4 预算提交
- [x] 月度考勤汇总

## 逾期未完成（1）
- [ ] 供应商资质年审（超期 2 天）

## 本周新增（2）
- [ ] ...

## 下周计划（2）
- [ ] 部门周例会（11-02 10:00）
- [ ] 月度报表（11-05 10:00）

## 统计
完成 3 · 逾期 1 · 进行中 2 · 循环任务 4
```

空章节保留标题并写「无」；报告不编造评价，不输出未在任务库中出现的事项。

## 8. 验收与发布门

- AC-REP-01：周报周期周一 00:00 至周日 23:59:59.999；月报自然月；
- AC-REP-02：单次完成任务可从主文件与 archive 聚合，无重复；
- AC-REP-03：循环任务完成 N 次时，报告准确显示 N 次（依赖 CompletionEvent）；
- AC-REP-04：逾期只列 active 单次，不含 paused/done/archived；
- AC-REP-05：复制/导出内容与预览一致；
- AC-REP-06：无记录显示空态，不报错；
- AC-REP-07：报告接口只读，调用前后 `tasks.json` 字节不变；
- AC-REP-08：schema v2→v3 迁移 + 旧数据兼容；
- 发布门：`tsc` 三份 0 错误；`node --test` 0 fail/0 skip；`verify-pack: OK`；现有 AC-01～AC-50 全过。

## 9. 风险与待拍板

| 风险 | 影响 | 处理 |
|---|---|---|
| 循环任务历史完成不可回填 | 0.2.x 已有循环完成记录无法进入历史报告 | 在 0.3.0 发布说明中明确“从本版本起记录”；不伪造历史 |
| 主文件事件增长 | `tasks.json` 变大 | 5000 条上限 + 24 个月裁剪；后续可独立 `events.json` |
| 归档跨季度读取慢 | 报告首次打开慢 | 只读跨周期相关 quarter；索引缓存；限制报告周期 |
| 报告口径争议 | 完成率/逾期定义不一致 | 先在 F11 中冻结统计口径，再实现 |

**建议拍板项（默认值）**：

1. 报告**包含循环任务完成次数** → 需要 schema v3（推荐）；
2. 输出 **Markdown + 复制 + `.md` 导出**（推荐）；
3. 周报 **周一至周日**、月报自然月（推荐）；
4. 不调用 LLM，确定性模板（推荐）。
