## 2. 仍需处理的 P0（唯一开工阻断）

### P0-1 schemaVersion 3→4 只改了规划，主需求文档仍写 v2

0.7.0 规划已经把本次迁移定为 **3→4**（`0.7.0版本规划.md:74、77、157、186`），需求 v1.20 的 F5.13 也写了「schemaVersion 3→4」（`需求-v1.md:384`），但主需求中仍有多处旧口径：

| 位置 | 当前内容 | 问题 |
|---|---|---|
| `需求-v1.md:398`（F6.8） | 「**主文件、归档 quarter、archive/index.json 都必须使用同一个 `SCHEMA_VERSION=2`**；quarter 执行 1→2……v1 文件被 v2 插件读取……」 | 0.7.0 当前实际基线是 schema 3，目标为 4；若按此实现会漏掉 v3→v4、归档/index 迁移 |
| `需求-v1.md:464`（F9.5） | 「构造 v1 主文件/季度文件/index 样本均升级到 **v2**」 | 迁移链目标错误；应为 v4（并保留 v2→v3→v4 的链） |
| `需求-v1.md:670`（§7.4 示例） | `"schemaVersion": 2` | 数据模型示例过期；0.6.0 实际是 v3，0.7.0 目标 v4 |
| `需求-v1.md:1322`（AC-41） | 「所有迁移链路……均升到 `schemaVersion=2`」 | 验收预期错误 |
| `README.md:238`（DEV-10） | 「`schemaVersion > 2` 的归档 quarter……留到 v2 真正出现时处理」 | 当前实际 schema 3，0.7.0 将到 4；该备注需要更新或删除 |

**后果**：开发 N0 时会出现「按 F6.8/F9.5 写 v2 迁移」和「按 F5.13/0.7 规划写 v3→v4」两套目标；归档 quarter/index 是否迁到 4、旧 v2/v3 文件如何处理无法判定，属于数据迁移级 P0。

**建议**：一次改齐：

- F6.8：改为 `SCHEMA_VERSION=4`，明确主文件/归档 quarter/`archive/index.json`/`POST /import` 同一迁移链；
- F9.5：迁移链目标改为 v4，保留 v1→v2→v3→v4 路径；
- §7.4 示例：`"schemaVersion": 4`；
- AC-41：改为 v1/v2/v3 样本升级到 v4（或新增 AC-70 覆盖 v3→v4，AC-41 保留历史 1→2 的验证意义）；
- README DEV-10：改为当前 `SCHEMA_VERSION=3`，0.7.0 目标 4，归档 quarter 的 v4 读取/恢复按当前版本处理。

> 这一项改完后，0.7.0 就可以正式进入 N0；其余上一轮问题已不再阻断。

## 3. 仍需注意的 P1（不阻塞 N0，但应在 N0/N1 前定稿）

### P1-1 F7.2/F7.3 未说明新任务 `notify.channels` 的服务端处理

- F5.14 要求新任务 `notify.channels=["overlay"]`，但 `F7.2 todo_reminder_create` 仍只写 `notify?`，没有说明旧客户端传 `notify.channels=['system']` 时是拒绝、忽略还是强制覆盖；F7.3 编辑旧任务也未说明是否保留 system 字段。
- 建议在 F7.2/F7.3 增加验收：创建时服务端强制 overlay；编辑旧任务保留旧 system 值但不用于投递；与 AC-67 对齐。

### P1-2 Settings JSON / `SettingsPayload` 字段表尚未补 `desktopNotifications`

- 0.7.0 规划已定义 `Settings.desktopNotifications`，但 `需求-v1.md` 的 §7.4 settings JSON 示例（`:676-682`）仍没有该字段；`src/client/api.ts` 的 `SettingsPayload` 当前也没有（`:78-85`）。
- 规划 N0/N2 已覆盖代码，但需求数据模型要同步补字段（默认 false、可选兼容），否则实现与验收文档不一致。

### P1-3 旧 0.6.0 读 v4 的 `unsupported-version` 行为需在 AC-68/README 统一

- 规划 §2.2/AC-68 已写「旧 0.6.0 读 v4 拒绝并只读」；但 `F6.8` 仍写 v2 插件读 v1 的旧例子；建议在 F6.8 增加 v3 插件读 v4 的明确表述，并让 `health.storage.state="unsupported-version"`、文件不覆盖。
