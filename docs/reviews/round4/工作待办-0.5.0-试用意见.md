# 工作待办 0.5.0 真实试用意见

> 试用角色：综合管理部主管（行政 / 文秘 / 跨部门协调）
> 试用版本：`dsh-todos-diy@0.5.0`（commit `456c99c`，独立临时 `DSH_HOME`，未触碰真实库）
> 试用方式：真实页面操作（ego-browser）+ 真实数据录入 + 周报/月报生成
> 试用日期：2026-10-31

## 0. 结论

**0.5.0 可以日常使用，周报/月报解决了“每周手工汇总”的真实痛点。** 核心流程（建任务 → 页签管理 → 完成 → 一键周报）顺畅，D-25 的截止/优先级语义在页面上表达正确。仍需优化 2 个 P1 体验点（搜索范围、NLP 降级提示）与 4 个 P2 细节。

## 1. 试用场景与数据

我按综合管理岗一周的真实工作录入 16 条任务：

| 类型 | 示例任务 |
|---|---|
| 会议组织 | 部门周例会（每周一 09:00，循环） |
| 公文流转 | 公文流转台账归档 / 核销（单次，已完成） |
| 合同管理 | 供应商合同评审、供应商资质年审（超期） |
| 预算财务 | Q4 预算申报、部门预算执行分析（每月末） |
| 人事考勤 | 月度考勤汇总（每月 28 日）、年度培训报名（已完成） |
| 接待协调 | 接待方案（市领导调研）（已暂停） |
| 资产管理 | 资产盘点 |
| 印章管理 | 印章使用登记（每工作日 17:30） |
| 领导交办 | 领导交办事项台账、跨部门项目跟踪 |
| 例行汇报 | 交周报（每周五 17:00，提前 10 分钟） |

页面状态：`未开始 1 / 进行中 5 / 已超期 1 / 已完成 4`，独立筛选 `循环任务 4 / 已暂停 1`，与后台 counts 一致。

## 2. 用得顺的地方

1. **四阶段页签 + 循环/暂停独立筛选**：一眼看清“今天该干什么、什么已经超期”，比旧的 todo/done 两视图清晰很多。
2. **优先级分组**：置顶 → 高 → 中 → 低 → 无，自动分组；置顶任务自动排在最前（实测置顶 Q4 预算后从第 3 位升到第 2 位，置顶组内按优先级排序）。
3. **行摘要**：单次任务显示 `09:00 → 18:00`；只填截止时间的任务显示「单次 · 截止 2026-11-02 18:00」，不会虚构开始时间。
4. **完成交互**：勾选即完成，超期页签的计数立即减少、已完成增加，并支持撤销。
5. **报告**：顶部「生成报告」→ 周报/月报 Tab + 本周/上周/本月/上月，结构完整（本周完成/逾期未完成/本周新增/下周计划/统计），这次试用的周报统计为 `完成 4 · 逾期 1 · 进行中 5 · 循环 4`，完成率 80%，数字与页面 counts 一致；复制/导出可用，导出文件名 `工作周报-2026-10-26.md`。
6. **空搜索**：无匹配时有明确空态「没有找到匹配…的任务」+「清除搜索」按钮，不会误以为系统坏了。
7. **隐私**：设置里自然语言开关默认关闭，开启前有明确说明。

## 3. 问题与优化建议

### P1-1 搜索只在当前页签内生效，容易漏任务

- **复现**：切到「已超期」页签，在搜索框输入“预算” → 空结果（提示无匹配）；切到「进行中」再搜“预算”才出现「Q4 预算申报」。
- **影响**：综合岗找任务时通常不记得它在哪个阶段；搜不到会误判“任务丢了/没建”。
- **建议**（按成本从低到高）：
  1. 空态增加「在当前视图无匹配，去全部任务中搜索」按钮（一键跨视图）；
  2. 搜索时自动跨视图（全局搜索），结果按阶段分组；
  3. 搜索框旁增加范围切换「当前视图 / 全部任务」。
- 现有 placeholder「在当前视图内搜索」只能起提示作用，不能避免误判。

### P1-2 自然语言解析降级时没有任何提示

- **复现**：开启自然语言新建，输入「每周五下午5点提醒我交周报，提前10分钟」→ 直接打开任务编辑器，标题是整句原文、类型为「单次」、结束时间为空，**没有任何“解析失败/已保留原文”的提示**。
- **实测原因**：本机 CLI profile 下 `/parse` 返回 `degraded=true, reason=bad_output`（模型返回非 JSON）。
- **影响**：用户会以为“它没听懂但也不说”，体验像坏了一半；且原文整句被当成标题，需要手动删改。
- **建议**：降级时保留原文的同时，在编辑器顶部显示横幅「自动解析暂不可用，已保留原文，请手动补充」+「重试解析」按钮；设置/日志里可看原因（不影响普通新建）。

### P2-1 「本周期新增」条目过多，报告可读性下降

- **复现**：本周集中录入 16 条任务后，周报「本周新增（16）」一次性列出全部（含已完成）。
- **影响**：周报是给领导看的，新增列表过长会淹没“完成/逾期”两个重点。
- **建议**：新增章节默认只列**未完成**的新增任务（已完成可折叠），或按「单次/循环」分组；超过 10 条时显示「其余 N 条已折叠」。

### P2-2 Toast 文案重复

- **复现**：完成任务后 toast 显示「已完成 · 撤销 撤销」（文案里带“撤销”，右侧按钮也叫“撤销”）。
- **建议**：文案改为「已完成」，按钮保留「撤销」；或文案「已完成，可撤销」。

### P2-3 保存编辑后的反馈不明显

- **复现**：修改任务标题保存后，列表已更新，但未观察到明确的成功 toast（可能被面板刷新吞掉/时序问题）。
- **建议**：保存成功统一 toast「已保存」；失败保留错误提示。

### P2-4 行首完成按钮的识别度仍偏弱

- **现象**：行首圆圈内的 ✓ 颜色较浅，静态截图下不够像“可点击的完成按钮”，hover 后才明显（UX-20 方向正确，但默认态还可再强化）。
- **建议**：默认态加深 ✓ 或使用描边圆 + 浅灰勾，hover 变主题色。

### P2-5 报告缺“备注/说明”输入

- 管理岗交周报时常要补一句“本周重点：XX 项目验收”。当前报告只能生成不能补充文字（规划里列为 P1 可选）。
- **建议**：报告弹窗增加一个「备注」文本框，追加到 Markdown 末尾（不写入任务数据）。

### P2-6 分组折叠在大数据量下待验证

- 本次「进行中」6 条按优先级分成 3 组（置顶 2 / 中 1 / 无 3），每组 ≤5，未触发「展开剩余 N 条」；需要 30+ 条同组数据再验证折叠阈值与展开状态。

## 4. 对 0.5.0 周报/月报的评价

- **优点**：一键生成、结构固定、不调用 LLM（可解释、可复制给领导）、完成率/逾期/进行中/循环四个数字一眼可用；周/月与本周/上周/本月/上月切换顺手。
- **最想要的两点**：① 新增列表收敛（P2-1）；② 报告加备注（P2-5）。
- **暂未用到**：归档季度在报告中的合并（本次数据都在当前季度），已由测试覆盖。

## 5. 总评

| 维度 | 评分（5 分制） | 说明 |
|---|---|---|
| 信息架构 | 4.5 | 四阶段 + 分组 + 优先级，符合管理岗心智 |
| 录入效率 | 4 | 常规表单顺手；NLP 降级路径需提示 |
| 任务管理 | 4.5 | 完成/暂停/置顶/搜索齐全，搜索范围需优化 |
| 报告价值 | 4 | 结构完整、数字可信；新增列表与备注可优化 |
| 视觉与反馈 | 3.5 | 整体清爽；完成按钮与 toast 细节可打磨 |

**结论**：0.5.0 达到“可日常使用”的水平，建议按 P1-1/P1-2 优先修复后再做一次小版本（0.5.x）体验收口，其余 P2 可进 0.6.0 批次。
