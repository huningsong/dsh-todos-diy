# 第二轮页面体验问题评估

> 评估对象：[工作待办-页面操作体验（第二轮）.md](../../../工作待办-页面操作体验（第二轮）.md)
> 评估时间：2026-10-30 ｜ 运行版本：`0.2.0`（`/health` 实测）
> 结论：**上一轮 3 个 P0 已修复；第二轮 8 个问题中 7 个真实存在，1 个主要是控件体验/偏好；需要修复 5 个，P1-A 排 0.2.1，P2-G 可延后。**

## 1. 逐条判断

| 编号 | 报告问题 | 真实？ | 证据 | 处理建议 |
|---|---|---|---|---|
| **P1-A** | 循环任务未触发前点「完成」报「当前没有可完成的提醒」 | **真实** | `src/host/repo.ts` 的 `complete()` 在 `lastOccurrenceKey === null` 时抛 `no_occurrence`；当前无 `skipNext` | **0.2.1 F7.18 修**：允许 `complete({skipNext:true})` 跳过下一次 occurrence；保留无 `skipNext` 时旧错误 |
| **P1-B** | 「循环任务」筛选偶发徽标有数、列表为空 | **真实（竞态）** | `src/client/panel.ts:71-91` 的 `load()` 没有请求序号/AbortController；切换视图时旧响应可覆盖新响应 | **应修**：`requestSeqRef` 或 `AbortController` 只接受最后一次响应；加载中显示骨架屏，不显示“空” |
| **P2-C** | 未填结束时间只提示「参数不合法」 | **真实** | `src/client/task-editor.ts` 只本地校验标题/起止顺序；`dictionary-zh.ts:198` 将 `invalid_argument` 统一翻译为“参数不合法”，没有字段级提示 | **应修**：前端对 `once.endAt` 空值直接标红并提示“结束时间为必填”，后端 message 保留字段定位 |
| **P2-D** | 设置弹窗按钮写成「保存任务」 | **真实（文案 bug）** | `src/client/settings-modal.ts:67` 使用 `t('form.save')`；`dictionary-zh.ts:122` 的 `form.save` 是「保存任务」 | **立即修**：新增 `settings.save: 保存设置` / `Save settings`，设置弹窗改用该 key |
| **P2-E** | 「仅截止」任务行仍显示开始时间 | **真实** | `src/client/task-row.ts:40-45` 的 `ruleSummary()` 对 once 无条件拼 `startAt → endAt`，未判断 `once.startAtSource === 'created'` | **应修**：`startAtSource==='created'` 时只显示「单次 · 截止 ...」；显式开始才显示区间 |
| **P2-F** | 搜索只过滤当前页签 | **真实（行为）** | `src/client/panel.ts` 的 `load(view, search)` 把当前 `view` 一起传给 `/snapshot`，搜索受视图限制 | **先定产品口径**：要么改全局搜索（忽略当前 view，按 `q` 搜全部非 archived），要么在搜索框明确标「当前视图内搜索」 |
| **P2-G** | 日期时间控件分段输入、程序化 fill 麻烦 | **真实（浏览器控件行为），但不是代码 bug** | 使用原生 `input[type=datetime-local]`；Chromium 的 segmented 控件就是这样 | **降级为体验增强**：可加日历弹层/快捷项（今天/明天/下周一/本月末），不阻塞 0.2.0；不建议为了自动化改控件 |
| **P2-H** | Agent `list()` 默认返回空、循环任务被隐藏 | **真实** | `src/host/toolDefs.ts:84` 默认 `args['view'] ?? 'inProgress'`；`recurring` 是独立 stage，不在 `inProgress` | **0.2.1 F7.16 修**：工具默认 `view="all"`，HTTP 保持 UI 默认 `inProgress` |

## 2. 必须修复的优先级

### 立即（本轮 0.2.x 小修）

1. **P2-D 文案**：1 处字典 key，风险极低。
2. **P1-B 竞态**：影响“筛选后无数据”的信任，必须修。
3. **P2-E 仅截止显示**：与 D-25 模型不一致，容易让用户误以为系统仍保留开始时间。

### 0.2.1（与 P1 体验批次一起）

4. **P1-A `skipNext`**：循环任务提前完成，主操作场景。
5. **P2-C 字段级校验**：表单必填项就地提示。
6. **P2-H / F7.16 Agent 默认 all**：与 P1-4 同一问题。
7. **P2-F 搜索**：先确认全局/当前视图口径，再决定是否改代码。

### 可延后

- **P2-G 日期控件**：原生控件可用，改造成本大于收益；作为 v1.1 UI 增强。
- 报告第五节的模板/批量/日历/ICS/提醒升级：沿用上一轮结论，留 0.3.0/v1.1。

## 3. 是否需要修复产品模型

**不需要。** 第二轮问题全部是客户端交互、文案、请求竞态、单个工具默认值，不涉及 D-25 数据模型或状态机。P1-A/P2-H 属于 Agent 体验补齐（0.2.1），P1-B/P2-C/D/E 属于 0.2.x UI/客户端小修。

## 4. 回归补充

修完上述项后，至少补：

- P1-B：模拟旧 snapshot 延迟返回，切视图后只接受新结果；
- P2-C：不填 endAt 保存 → 字段标红、提示“结束时间为必填”，不出现“参数不合法”；
- P2-D：设置弹窗显示「保存设置」；
- P2-E：`startAtSource=created` 行只显示截止；
- P1-A：新建循环任务 `complete({skipNext:true})` 成功，下一次触发从再下一次开始；
- P2-H：`todo_reminder_list()` 默认返回所有活跃/待办阶段（含循环、未开始、超期、暂停），不是空数组。
