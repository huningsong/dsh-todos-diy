## 三、提交 PR

1. Fork [awesome-dsh-plugin](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin)
2. 把本仓库的 [`docs/market/huningsong__dsh-todos-diy.yml`](huningsong__dsh-todos-diy.yml) 复制到 fork 的 `data/plugins/` 目录下
   （文件名必须是 `huningsong__dsh-todos-diy.yml`，`__` 分隔 owner 和 repo）
3. 提交 PR，标题建议：`Add huningsong/dsh-todos-diy`
4. PR 描述里可以写：`Adds a work todo reminder plugin with four stage views, recurring/paused filters and derived priority. Entry file only; READMEs are generated.`

> ⚠️ **只加一个文件**，不要手改 README（README 由脚本生成）。PR 最多加 3 条。

## 五、可选：发布到 npm（能提升展示效果）

发布 npm 后市场会显示下载量，并让安装跳过源码构建。**不影响收录**。

```bash
cd /Users/huningsong/Desktop/work/tmp/dsh-todos-diy
npm adduser          # 或 npm adduser --registry=https://registry.npm.fe.ioteams.com
npm publish
```

注意：已发布包的 `package.json` 里 `repository` 字段必须指回本仓库（已配好），否则市场不会把包和条目关联起来。发布后**不要在条目里手写 `npm:` 字段**（会被校验拒绝，映射自动采集）。

## 六、可选：预构建 tarball

如果担心用户从源码装（`github:` 会触发 pnpm 的 `allowBuilds` 授权），可以给 GitHub Release 附一个预构建 tgz，并在条目里加：

```yaml
tarball: https://github.com/huningsong/dsh-todos-diy/releases/latest/download/dsh-todos-diy.tgz
```

然后重新渲染图标/截图不必动——截图已经在 `screenshots.json` 里声明，市场会自动读取。

> 我们的仓库**没有** `prepare` / `postinstall` / `prepack` 脚本，`lib/` 已提交，所以从源码装也不会触发构建授权。tarball 只是锦上添花。
