# 周报 / 月报功能评估与需求设计

> 结论：**值得做，建议作为 v0.3.0 / v1.1 的 P1 功能，不混入 0.2.1。**
> 但先要定一个数据口径：**循环任务的“完成历史”目前没有持久化，无法准确统计**；如果周报必须包含循环任务完成次数，需要先补完成事件日志（schema v3）。

## 1. 推荐 MVP

一键生成「周报 / 月报」，默认**确定性模板**，不调用 LLM：

- 入口：主面板顶部「生成报告」按钮；
- 周期：
  - 周报：本周（周一 00:00 – 周日 23:59:59.999，设置时区）
  - 月报：本月（1 日 00:00 – 月末 23:59:59.999）
  - 支持「本周 / 上周 / 本月 / 上月」切换；
- 预览：`ReportModal` 内 Markdown 预览；
- 输出：复制 Markdown / 导出 `.md`；
- 内容：
  1. **本周期完成**：单次任务按 `doneAt` 统计（含已归档季度）；
  2. **逾期未完成**：当前 `active` 且 `endAt < now` 的单次任务；
  3. **本周期新增**：`createdAt` 在周期内的任务；
  4. **下周期计划**：`nextAt`/`endAt` 落在下周期的 active 任务；
  5. **统计**：完成数、逾期数、进行中、循环任务数、完成率（可先只给数字，不编造评价）；
  6. 可选「备注」输入，用户可补充文字。

示例：

```markdown
# 工作周报（2026-10-26 ~ 2026-11-01）

## 本周完成（3）
- [x] 供应商合同评审
- [x] Q4 预算提交
- [x] 月度考勤汇总

## 逾期未完成（1）
- [ ] 供应商资质年审（超期 2 天）

## 下周计划（2）
- [ ] 部门周例会（11-02 10:00）
- [ ] 月度报表（11-05 10:00）

## 统计
完成 3 · 逾期 1 · 进行中 2 · 循环任务 4
```

## 2. 关键数据缺口：循环任务完成历史

当前模型：

- `Task.doneAt` 只对单次任务写入；
- 循环任务 `complete` 只把 `state.completedOccurrenceKey` 更新为**最近一次**，状态仍是 `active`；
- `DeliveryRecord` 记录投递/已读/忽略，**不记录完成动作**。

因此：

- 单次任务周报：可从 `doneAt` + 归档任务准确统计；
- 循环任务周报：**只能知道最近一次完成，无法统计本周/本月完成了几次**。

### 建议：新增完成事件日志（若循环任务必须进报告）

```ts
interface CompletionEvent {
  id: string
  taskId: string
  taskTitle: string        // 快照，防任务删除后无法报告
  kind: 'once' | 'recurring'
  occurrenceKey: string
  completedAt: string      // ISO
  dueAt: string | null     // 单次 endAt / 循环 occurrence 时间
}
```

- 在 `PersistedState` 增加 `completions: CompletionEvent[]`；
- 单次、循环 `complete` 都追加一条；
- 保留最近 N 条（建议 5000 或 24 个月），滚动裁剪；
- `schemaVersion 2→3`，v2 旧数据补空数组；历史单次 `doneAt` 可在迁移时回填为 `CompletionEvent`，循环历史不可回填（明确告知）；
- 报告读取主文件 + 相关归档季度，按 `completedAt` 聚合。

**如果不想改 schema**：MVP 可明确只统计“单次任务完成 + 当前逾期/待办”，循环任务只统计当前数量，不统计完成次数；但报告会缺一块，管理岗可能不买账。

## 3. 服务与 API

建议新增只读接口，报告不落盘：

`GET /reports?kind=weekly|monthly&anchor=YYYY-MM-DD&timeZone=Asia/Shanghai`

返回：

```ts
interface ReportData {
  period: { kind: 'weekly' | 'monthly'; start: string; end: string; timeZone: string }
  completed: ReportTask[]
  overdue: ReportTask[]
  created: ReportTask[]
  upcoming: ReportTask[]
  stats: {
    completed: number
    overdue: number
    inProgress: number
    recurring: number
    completionRate: number | null
  }
  generatedAt: string
}
```

- 单次完成：`doneAt ∈ [start,end)`，含 archive 任务；
- 逾期：`active && kind=once && endAt < now`，不限本周期（报告“当前未办”）；
- 新增：`createdAt ∈ [start,end)`；
- 下周期计划：`nextAt`/`endAt ∈ [end, nextEnd)`。

报告生成不写 `tasks.json`，避免“打开报告产生副作用”。

## 4. 客户端

- 顶部「生成报告」按钮（与「新建任务」并列）；
- `ReportModal`：
  - Tab：周报 / 月报
  - 周期选择：本周 / 上周 / 本月 / 上月
  - Markdown 预览（等宽字体）
  - 操作：复制 / 导出 `.md` / 关闭
  - 可选「备注」输入，拼到末尾
- 不新增页面路由；复用现有 Modal 样式。

## 5. 非目标

- 不做自然语言总结/LLM 润色（可后续 v1.1 加开关）；
- 不做 Word/PDF 导出（先 Markdown；用户有需要再接 `office` 技能）；
- 不做“团队周报/多人汇总”；
- 不自动发送到邮件/IM。

## 6. 验收建议

- AC-REP-01：周期边界正确（周一 00:00 / 月末 23:59:59.999，设置时区）；
- AC-REP-02：单次完成任务含归档季度，无重复、无漏；
- AC-REP-03：逾期任务只列 active 单次，不含 paused/done/archived；
- AC-REP-04：周报/月报切换、复制、导出内容与预览一致；
- AC-REP-05：无完成记录时显示「本周期暂无完成事项」，不报错；
- AC-REP-06（若做事件日志）：循环任务完成 N 次准确，跨周/月聚合正确。

## 7. 需要拍板

1. **报告是否必须包含循环任务的完成次数？**  
   - 推荐：必须包含 → 先做 CompletionEvent/schema v3；  
   - 若只要单次任务，可先做轻量 MVP，循环只显示当前数量。
2. **输出格式**：推荐 Markdown 复制 + `.md` 导出；是否需要 Word/PDF？
3. **周报周期**：推荐周一至周日；是否按自然周（周一）还是周五至周四？
4. **是否允许 AI 润色**：推荐 v1.1 再加，默认关闭、按需开启。
