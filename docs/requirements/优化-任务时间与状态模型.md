# 优化建议：去掉截止日期，用「开始 / 结束时间」统一任务状态

> 日期：2026-10-30 ｜ 背景：目前 `dueDate`（截止日期）与 `once.endAt`（结束时间）语义重叠，已经出现「谁优先级更高」的歧义。
> 结论：**已拍板：删掉用户可见的 `dueDate`，把 `endAt` 定义为唯一截止时间；任务状态由 `stage` 读时派生，不落库。**

---

## 1. 问题诊断

当前模型同时存在：

- `dueDate`：日期级，仅用于优先级、超期、排序，不提醒；
- `once.endAt`：时间级，负责最后一次提醒，并触发单次任务自动完成。

由此产生三个问题：

1. **语义重叠**：一个任务到底“什么时候算到期”，两个字段可以给出不同答案。
2. **超期永远不出现**：当前单次任务在 `startAt`/`endAt` 两个节点都触发（或都 missed）后会自动置为 `done`。也就是说 `endAt` 一过任务就“完成”了，`dueDate` 再早也只会短暂显示超期，`dueDate` 再晚则永远不生效。
3. **无法表达「未开始」**：当前 `status` 只有 `active/paused/done/archived`，没有“还没到开始时间”的位置；所有未来任务都混在「待办」里。

**根因**：`endAt` 同时承担了“事件结束”和“任务截止”两种语义。必须先选一个。

建议：**`endAt` = 任务截止时间（deadline）**，`startAt` = 任务开始时间。

---

## 2. 建议的数据模型

### 2.1 单次任务

```text
startAt: ISO 8601，可选；不填 = 创建时间（创建即进入进行中；默认开始节点不产生开始提醒）
endAt:   ISO 8601，必填；必须晚于 startAt
```

- `startAt` 决定任务何时从「未开始」变成「进行中」。
- `endAt` 是唯一截止时间：过了就是「已超期」。
- 不再有 `dueDate`。
- `startAt` 省略时 `once.startAtSource="created"`，只排 `#end` 提醒；显式填写才排 `#start` 与 `#end` 两个提醒。

### 2.2 循环任务

```text
rule.time: 每次 occurrence 的触发时间（= 本期截止时间）
rule.durationMinutes: 可选，默认 0；填了就有“开始~结束”的窗口
```

- 循环任务没有单一的 `startAt/endAt`，它的“开始/结束”是每一次 occurrence 的。
- 如果不填 `durationMinutes`，每次 occurrence 是一个时间点，只显示「下次触发 周五 17:00」，不参与「进行中」。
- 如果填了，例如「每周五 09:00–17:00」，则每周五 09:00–17:00 为「进行中」。

### 2.3 状态模型（两层）

**持久化状态**（仍只有四个）：

`status: active | paused | done | archived`（`done` 仅单次任务；循环任务只有 `active/paused/archived`）

**派生阶段**（只读、不落盘、每次读取按当前时间计算）：

| 阶段 | 判定 |
|---|---|
| `notStarted` 未开始 | `now < startAt`（**注意：开始时间大于当前时间**） |
| `inProgress` 进行中 | `startAt ≤ now < endAt` |
| `overdue` 已超期 | `now > endAt` 且 `status = active`（`endAt` 当秒仍算进行中） |
| `done` 已完成 | `status = done` |
| `paused` 已暂停 | `status = paused` |
| `recurring` 循环中/待触发 | `status = active` 且 `kind = recurring`；未开始/进行中/已超期只对单次任务 |

> 你原话「未开始 = 开始时间小于当前时间」方向反了：
> - 开始时间 **大于** 当前时间 → 还没开始 → 未开始
> - 开始时间 **小于** 当前时间 → 已经开始 → 进行中（若已过 endAt 则是已超期）

**刷新方式：取消「每日 00:05 重算」。**

- `stage` 与 `priority` 都是读时派生，每次 `GET /snapshot` 用同一个 `now` 计算，不落盘；
- 客户端在所有任务中最近的未来边界（`startAt`/`endAt`/`nextAt`）到点时刷新一次（容错 1 秒），兜底每 60 秒；
- 这样今天 16:00 开始的任务，15:59 显示「未开始」、16:00:01 显示「进行中」，不会等到次日 00:05；
- 00:05 只保留日级维护（归档、清理），不再承担状态/优先级刷新。

**关键改动：取消 `endAt` 自动完成。**

- 现在的 `applyTick` 在单次任务两个节点都 settled 后自动 `done`，必须去掉；
- `endAt` 只表示“截止时间到了”；显式 `startAt` 时默认开始/结束各提醒一次，省略 `startAt` 时只排 `#end`；`notify.endReminder=false`（会议类）只排 `#start`；
- `done` 只能由用户点「完成」或 Agent 调 `complete` 产生；
- 这样 `now > endAt` 且未完成才会进入「已超期」，统计才有意义；`endAt` 当秒仍算进行中。

## 3. 统计设计

### 3.1 API

`GET /snapshot` 的 `counts` 扩展为：

```json
{
  "counts": {
    "notStarted": 3,
    "inProgress": 2,
    "overdue": 1,
    "done": 12,
    "paused": 1,
    "recurring": 3
  },
  "byKind": { "once": 18, "recurring": 3 },
  "totalDone": 37
}
```

- `notStarted/inProgress/overdue` 只统计单次任务；`recurring` 只统计 active 循环任务；`paused` 独立；
- `done` 统计主文件本季度已完成；`totalDone` 含历史归档（`archive/index.json` 各季度 count，按 id 去重）；
- `byKind` 是全部非归档任务类型计数；
- 全部读时计算，不落盘，不需要定时任务。

### 3.2 UI

**推荐：4 个阶段页签 + 循环 / 暂停独立筛选**

```text
[未开始 3] [进行中 2] [已超期 1] [已完成 12]
循环任务 3 · 单次任务 18 · 已暂停 1
```

- 「未开始」= 未来才开始的单次任务；
- 「进行中」= 已开始未结束的单次任务；
- 「已超期」= 已过 endAt 且未完成的单次任务；
- 「已完成」= done（默认本季度，可切换历史归档）；
- 「循环任务」= active 循环任务独立筛选，阶段 `recurring`；
- 「已暂停」= 独立筛选/折叠区，不混入任何阶段页签；
- 每个页签的数字就是该阶段数量；循环/暂停各自单列。

> 如果你说的「每类任务」是指自定义分类（会议 / 报表 / 培训），那需要另加 `category` 字段，和状态统计是两回事。

## 4. 对现有功能的影响

| 模块 | 改动 |
|---|---|
| 数据模型 | 删除 `Task.dueDate`；`TaskView` 增加 `stage`，`priority` 改为 `{key, remainingMinutes}`，基于 `endAt`/`nextAt` 实时计算 |
| 状态机 | 单次任务不再自动 done；`done` 仅手动/工具调用 |
| 视图 | 四个阶段页签 `notStarted/inProgress/overdue/done` 只覆盖单次任务；循环 `recurring`、暂停 `paused` 独立筛选 |
| 优先级 | `derivePriority(task, now)`；单次按 `endAt`、循环按 `nextAt`；阈值用半开区间 24h/72h/168h，`remainingMinutes` 向下取整 |
| 排序 | pinned → priority → endAt（循环 nextAt）→ title |
| 表单 | 删除「截止日期」字段；单次任务保留「开始时间（可空）/结束时间（必填）」；`notify.endReminder`；循环 `durationMinutes` 留 v1.1 |
| API/工具 | `todo_reminder_create/update` 去掉 `dueDate` 参数；`TaskView` 增加 `stage`；`counts` 扩展 |
| 迁移 | `schemaVersion` 1→2：删除 `dueDate`；旧单次任务保留 `endAt`；旧循环任务如带 `dueDate` 直接丢弃；旧单次任务若缺 `endAt` 判 `migration-failed` 并保留原文件（不假设无历史数据） |
| 文档/测试 | F4.11、F4.12、D-20、D-22、AC-31/35/36/37 需要重写；priority/view 测试全部更新 |

**工作量估算（评审校准）：8.6–13.0 人日**（单人串行，含测试重写、归档三链路迁移、客户端与 i18n）；3 人并行约 6–8 个工作日。

## 5. 建议的落地顺序

1. **先定 `endAt` 语义**：截止时间，不是“事件结束时间”。
2. 改数据模型 + `schemaVersion` 迁移（删 `dueDate`）。
3. 改状态派生（`stage` 七态）+ 取消自动 done。
4. 改视图/排序/统计 counts。
5. 改表单/工具/文档/测试。
6. 回归：创建未来任务 → 未开始；到 startAt → 进行中；过 endAt 未完成 → 已超期；完成 → 已完成。
